# AI 辅助游戏自动化框架 · 架构设计文档

> 状态：设计稿 v0.1（2026-10-12）
> 背景：基于 OnmyojiAutoScript（OAS）长期维护经验，设计下一代游戏自动化框架的选型与架构。
> 结论先行：**确定性流程为主体 + 语义化感知 + 事件驱动的 VLM 监督层**，常态开销与现有 OAS 相当，异常处理能力质变。

## 1. 背景与动机

OAS 以"模板资产 + 确定性状态机"驱动，长期稳定运行，但在 2026-10 游戏全面 UI 改版期间暴露出三层结构性脆弱（以下均有实测案例）：

| 层 | 痛点 | 实测案例 |
|---|---|---|
| 感知层 | 模板匹配是像素级对齐，UI 改版/位移/明暗变化即失配 | 勋章商店 8 商品资产全部过期；购买弹窗按钮随描述行数纵向漂移 27px |
| 流程层 | 循环"只识别不决策"，遇到未知状态没有出路 | 未注册页面（游戏内联动页）逃生循环 15 次点穿；奖励弹窗渲染延迟被误判"弹窗已关" |
| 恢复层 | 出错后静默空转，60s 防卡死兜底后直接杀任务 | 选魂界面标志失配导致纯识别空转；商品位置漂移后 OCR 定位错乱误判 0 次 |

同时，OAS 的**执行层（minitouch / nemu_ipc）、调度器、防卡死机制、多账号管理**经过长期验证非常成熟，是必须保留的资产。近期修复过程中积累的报错截图库（`log/error/`）是高价值的感知层训练素材。

## 2. 设计目标

1. **低开销**：常态（99% 时间）单帧感知开销 ≤ 30ms（CPU），与现有模板匹配方案相当；AI 推理不进入逐帧路径
2. **抗变化**：UI 改版、元素位移、配色/明暗变化不需要重新裁资产；只需（周期性地）微调检测模型
3. **自愈**：未知状态、意外弹窗、流程卡死可自动恢复，恢复动作可控可回放
4. **可迁移**：现有任务逻辑、执行层、调度器最大化复用，不推倒重来
5. **可解释**：每个动作可追溯（哪个状态、哪条规则/哪次 AI 决策触发）

## 3. 总体架构

```
┌─ 模拟器实例 ×N ─────────────────────────────────────────┐
│  [执行层 minitouch/nemu_ipc] ←──动作── [流程引擎·状态机]   │
│        ↓ 帧(跳帧)                        ↑ 语义条件       │
└─────────┼────────────────────────────────┼──────────────┘
          ↓                                │
   [感知服务·单例·batch]  ──场景语义JSON──→─┘
   YOLO-nano 检测 + 轻量 OCR
          ↓ 未知状态/卡死（事件驱动）
   [VLM 监督者] ──恢复动作(结构化JSON)──→ 注回运行时
          ↓ 成功案例
   [样本闭环] → 人工审核 → 检测器微调
```

核心原则：**AI 放在监督层（事件驱动），不放感知层（逐帧驱动）**。低开销的关键是调用频率而非模型大小：

- 常态路径全部确定性：感知服务输出"场景语义 JSON"，流程引擎消费语义字段做状态转移，可预测、可回放、零 token
- VLM 仅在状态机自己走不动时被调用一次，输出结构化动作后立即交还确定性流程
- 感知服务为单例共享（多实例 batch 推理），跳帧：画面帧差无变化则复用上次结果

## 4. 分层设计

### 4.1 感知服务（Perception）

- **目标检测**：YOLO-nano 级模型替代模板匹配。一个类别一个检测器（或单模型多类），输出类别+置信度+边界框，天然容忍样式微调、位置漂移、明暗差异
- **文字识别**：轻量 OCR（RapidOCR / PaddleOCR-mobile）按需读取语义数值（剩余次数、价格、数量），仅对检测到的元素区域做 OCR，不做全屏
- **输出契约**：场景语义 JSON，形如：

```json
{
  "page": "mall.medal",
  "elements": {
    "buy_dialog": {"visible": true, "item": "challenge_pass",
                    "quantity": 1, "price": 30,
                    "max_button": {"x": 780, "y": 460, "w": 46, "h": 48}}
  },
  "frame_id": 10293
}
```

- **关键约束**：语义 JSON 是感知层与流程层的**唯一契约**。UI 改版只需重训/微调检测器并更新 JSON schema（如新增字段），流程层零改动
- **兼容层**：提供与 OAS `appear()/appear_then_click()` 签名兼容的适配器，内部实现从模板匹配切换为检测器查询，存量任务立即受益

### 4.2 流程引擎（Flow Engine）

- 保留确定性状态机/技能树写法（对齐现有 `script_task.py` 的组织方式）
- 状态转移条件从"资产命中"改为"语义字段条件"（如 `dialog.buy_button.visible && dialog.price <= budget`）
- 每个转移可附带 `on_unknown` 策略：`ask_supervisor` / `retry(n)` / `abort_gracefully`，杜绝"纯识别空转"

### 4.3 VLM 监督者（Supervisor）

- **触发条件**（事件驱动，非常态逐帧）：语义状态无法匹配任何已知状态、状态机停滞超阈值（沿用现有 stuck_record 思路）、连续 N 次动作无语义变化
- **输入**：当前帧截图 + 最近操作序列 + 当前任务意图（自然语言描述）+ 可用动作枚举
- **输出**：结构化 JSON 动作（点击坐标 / 按返回 / 关闭弹窗 / 跳过步骤 / 重启任务），**禁止自由文本执行**
- **失败约束**：连续恢复失败 2 次即触发任务级重启（复用现有 Restart 流程），不恋战
- **选型**：Qwen2.5-VL-7B-AWQ（本地，约 5GB 显存）或低价多模态 API；单次推理 1-3s，对恢复场景可接受

### 4.4 样本闭环（Data Loop）

- 采集源：报错自动落库截图（现有 `log/error/` 机制）、VLM 恢复成功案例、人工接管录像
- 人工审核一道闸，防止坏样本污染
- 定期增量微调检测器（LoRA/全参均可，nano 模型全参成本很低），评测集回归通过后发布
- 冷启动：OAS 历史截图 + "VLM 预标注 + 人工抽检"的主动学习流程，2-3 千张标注可覆盖主要场景

### 4.5 执行层（Executor）

- minitouch（点击/滑动）、nemu_ipc（高速截图）原样保留
- 新增：执行层动作接口标准化为 `execute(action_json)`，使 VLM 恢复动作与流程引擎动作共用同一执行通道

## 5. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 执行 | minitouch / nemu_ipc（复用 OAS） | 成熟稳定 |
| 感知 | YOLOv11n / RT-DETRv2-nano + RapidOCR | nano 级 CPU 可跑；检测框天然输出位置 |
| 推理运行时 | ONNXRuntime / OpenVINO（CPU 优先） | 多开共享模型实例 batch 推理 |
| 监督 | Qwen2.5-VL-7B-AWQ 本地 / 多模态 API | 函数调用输出 JSON；按可用硬件选择 |
| 语言/框架 | Python 3.10+（延续 OAS 技术栈） | 复用现有模块与团队经验 |

## 6. 性能预算

| 场景 | 开销 | 说明 |
|---|---|---|
| 常态感知 | ~15-30ms/帧（CPU） | 跳帧后实际更低；与现模板匹配方案相当 |
| 常态流程 | <1ms/转移 | 纯状态机 |
| 异常恢复 | 1-3s/次 × 每小时数次 | VLM 单次调用 |
| 多开 | 共享感知服务，增量递减 | batch 推理摊薄 |

## 7. 迁移路径

1. **阶段一：感知层替换**（不动流程）
   实现 `appear()` 兼容适配器，内部切检测器；存量任务全部受益；老模板资产转为检测器初始训练数据
2. **阶段二：监督者兜底**
   将现有 GameStuck/stuck_record 触发点接入 VLM 恢复；先对高频卡死任务（RichMan / Exploration）启用；建立样本落库
3. **阶段三：语义化新任务**
   新任务直接以语义条件编写；逐步把存量高频任务改写为语义条件版本

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 标注成本高 | 主动学习：VLM 预标注 + 人工抽检；报错截图定向补充难例 |
| VLM 恢复不可靠 | 动作白名单 + 结构化输出；连续失败 2 次即重启兜底；恢复案例人工审核后才入库 |
| 检测器误检导致误操作 | 高危动作（购买/消耗）保留二次语义确认（价格、数量字段校验） |
| AI 依赖过重导致行为不可复现 | 常态路径零 AI；每次 AI 介入记录完整上下文可回放 |
| 多开资源竞争 | 感知服务单例化 + batch；VLM 串行队列限流 |

## 9. 与 OAS 的复用关系

| OAS 组件 | 处置 |
|---|---|
| minitouch / nemu_ipc / 调度器 / config / 多账号管理 | 原样复用 |
| 模板资产 | 转为检测器训练数据后退役 |
| 任务脚本 | 流程骨架保留，条件表达式迁移为语义字段 |
| GameStuck / stuck_record | 保留，作为监督者触发器 |
| log/error 截图库 | 冷启动训练集 |
